# ADR 0002: поколения и stop-before-start

Статус: принято как договор реализации; доказательства выполнения — в тестах и `../status.md`.

## Решение

Единица владения ресурсами — конкретное поколение компонента, а не строковый id и не ссылка на service object. Runtime выдаёт монотонную identity каждой регистрации и каждой попытке. Поколение фиксирует revision рецепта, activation/gate epoch и выбранные поколения зависимостей.

Один сериализованный controller владеет desired graph, generations и publications. Его mailbox не теряет команды и lifecycle completion. Пользовательский acquisition, release и callback не выполняются внутри критического шага контроллера: исполнители сообщают результат отдельным событием.

При invalidation контроллер сначала отзывает публикации всей транзитивной ветки, включая Starting consumers и допущенные managed calls. Подтверждение команды означает применение desired change и отзыв публикаций, а не завершение I/O. Затем cleanup идёт от consumers к providers. Finalizer consumer вправе обращаться к старому provider: тот физически жив до завершения cleanup-попытки consumer.

Replacement выполняется строго stop-before-start. Не допускаются два живых поколения одного узла. Пока retiring-регистрация очищается, её id и export key зарезервированы. Задержавшийся completion проверяется по identity, а не только по строковому id.

## Scope и memoization

Каждой попытке принадлежат отдельные Scope и свежий MemoMap. Одинаковые sublayers внутри одной сборки разделяются обычным механизмом Effect; между поколениями memoization не переносится. Провайдеры передаются потребителям как borrowed service Context, а не повторно приобретаются через их Layer.

Контроллер должен оставаться жив до получения всех необходимых cleanup completion. Owning Scope вызывает упорядоченный shutdown runtime; случайный порядок закрытия дочерних scopes не определяет порядок графа.

## Последствия

- Допускается промежуток недоступности при replacement; zero-downtime не обещается.
- Нет автоматического возврата к уже закрытому старому экземпляру.
- Неизменённые ветви сохраняют identity и ресурсы.
- Ошибка release видна и блокирует автоматический restart: внешний ресурс мог остаться занят.
- Некоооперативный acquisition/callback/finalizer может удерживать Stopping и shutdown. Timeout ожидания не разрешает закрыть provider под живым consumer.
- `use` закрепляет одно поколение, не повторяет бизнес-команды и сохраняет среду вызывающего Effect. Запрет service escape — договор пользователя, не гарантия линейных типов TypeScript.

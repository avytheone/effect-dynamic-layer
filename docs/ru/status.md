# Состояние экспериментальной версии 0.1.0

[English](../status.md) | **Русский**

Библиотека реализована и проверена локально. В том числе завершён одобренный прямой переход от строковых идентификаторов узлов к управлению через сервисы `Context` и `LifecycleState`. Имя пакета npm — `@avytheone/effect-dynamic-layer`; версия `0.1.0` остаётся экспериментальной и не проверена в промышленной интеграции. Текущее состояние публикации указано ниже. Исходные требования зафиксированы в `HANDOFF-dynamic-layer.md`; владелец отдельно уточнил, что вместо исходной основы Effect 3.x, pnpm и Vitest следует использовать **Effect RC и Bun**.

Обычная команда `npm install @avytheone/effect-dynamic-layer` в новом внешнем приложении установила версию `0.1.0` и автоматически добавила `effect@4.0.0-rc.115`. Пример README скомпилировался TypeScript и завершился под Bun и Node. Первоначальные ответы об отсутствии пакета по закодированному пути реестра исчезли после распространения метаданных; установка проверена обычной командой npm, а не обходом реестра.

Договор выпуска:

1. Обновить версию в `package.json` и файле блокировки Bun, выполнить полный набор локальных проверок и зафиксировать проверенное состояние в коммите.
2. Для первой публикации версии `0.1.0` ровно один раз упаковать пакет, проверить этот самый архив командой `bun run test:package /absolute/path.tgz` и передать сопровождающему с явным разрешением для ручной публикации того же файла через `npm publish <tarball> --ignore-scripts --access public --tag latest` по действующему для учётной записи npm правилу 2FA для аутентификации и операций записи. Эта первоначальная публикация не заявляет подтверждение происхождения через CI.
3. После появления пакета настроить npm Trusted Publisher с указанными ниже полями.
4. Для каждой следующей версии обновить и проверить версию по шагу 1, а затем только при наличии разрешения на публикацию отправить точный тег `v${package.version}`.
5. `release.yml`, запускаемый только по тегам `v*`, проверяет точное совпадение тега и версии на GitHub-hosted Ubuntu, использует Bun из `.bun-version`, Node 24 и npm 11.12.1 и повторяет существующие проверки. Он ровно один раз собирает и упаковывает пакет через `npm pack` (`prepack` запускает сборку Bun), проверяет этот самый архив командой `bun run test:package /absolute/path.tgz` и публикует тот же файл через `npm publish <tarball> --ignore-scripts --access public --provenance --tag <latest|beta>` с меткой `beta` для предварительной версии и `latest` во всех остальных случаях.

GitHub Trusted Publisher создан командой `npm exec --yes --package=npm@11.19.1 -- npm trust github @avytheone/effect-dynamic-layer --file release.yml --repository avytheone/effect-dynamic-layer --allow-publish --yes` после интерактивного подтверждения 2FA. npm вернул сохранённую конфигурацию: тип `github`, репозиторий `avytheone/effect-dynamic-layer`, файл `release.yml`, без environment, права `publish` и `stage publish`. Постоянный `NPM_TOKEN` в GitHub не сохранялся; глобальная установка npm и закреплённая в процессе выпуска версия npm не обновлялись. Создание подтверждено ответом npm; отдельный неинтерактивный запрос `npm trust list --json` потребовал ещё одного подтверждения 2FA и не использовался как свидетельство повторного чтения настроек. Версия `0.1.0` опубликована вручную без подтверждения происхождения через CI. Выпуск через OIDC настроен, но его полной проверкой станет только последующая успешная публикация по тегу; повторно публиковать `0.1.0` не нужно.

Подготовка проверена локально: установка с замороженным файлом блокировки Bun, стиль, типы исходников и публичного API, все 68 тестов среды выполнения (231 проверка утверждений) и все три примера прошли. Успешны обе проверки приложения-потребителя: с самостоятельной упаковкой и с точным архивом выпуска. Обычная установка npm автоматически установила Effect; TypeScript скомпилировал публичные импорты и отклонил внутренние пути и прямой доступ к исходникам; жизненный цикл завершился с точным числом освобождений под Bun 1.4.2 и Node 24.15.0. Настоящий шаг упаковки из процесса выпуска и пробная публикация npm с `--dry-run` прошли; пакет не отправлялся. Actionlint 1.7.12 принял оба процесса. Настоящая проверка тега приняла обычную и предварительную версии с метками `latest` и `beta` соответственно и отклонила несовпадение тега с версией. ## Обнаруженные и исправленные проблемы

- Прерывание между завершением пользовательского ввода-вывода и отправкой сообщения о завершении сборки или условия запуска оставляло навсегда учтённую рабочую задачу. Протокол владения исправлен: прерываемым остаётся только ввод-вывод, а захват Exit и постановка сообщения о завершении защищены от прерывания.
- Закрытие области выполнения до выхода управляющего цикла могло прервать подтверждение для второго вызывающего shutdown. Теперь сначала управляющий цикл отправляет все подтверждения и завершается, и только затем закрывается область выполнения.
- Проверка состояния до асинхронной подготовки запроса оставляла гонку с shutdown перед постановкой запроса в очередь. Теперь после создания ответа окончательная проверка состояния и `Queue.offerUnsafe` выполняются одним синхронным шагом.
- Для области финализатора вызова, синхронного исключения из переданной функции, повторно используемых эффектов ожидания и изоляции после ошибки освобождения добавлены отдельные регрессионные сценарии и правильные пути очистки.
- `LayerMap` с нулевым значением `idleTimeToLive` по умолчанию не сохраняет значение между неперекрывающимися уже закрытыми владениями. Проверка совместимости исправлена так, чтобы проверять настоящий срок жизни владения.
- Квант планировщика 1 в выбранной предварительной версии не обеспечивал продвижение даже простого Effect без этой библиотеки. Проверки неблагоприятного планирования используют подтверждённый квант 16; временная исходная проба удалена.

Заключительный разбор исходного кода, посвящённый только жизненному циклу, не выявил существенных замечаний. Он дополняет исполняемые тесты, но не заменяет их.

## Уточнения API и известные ограничения

- В выбранной предварительной версии Effect используются `Context.Service`, `Layer.effect` с управляемым временем жизни ресурсов, `Layer.unwrap` и локальный для дочерней задачи `Context.Reference`. API Effect 3 — `Context.Tag`, `Layer.scoped` и `Layer.unwrapEffect` — с этим API не смешивается.
- После одобренного прямого перехода методы `enable`, `disable`, `retry`, `unregister`, `replace` и `awaitState` принимают сервис `Context`; строковых перегрузок и псевдонимов нет. Для ожиданий экспортируется `LifecycleState`; поле `id` узла остаётся диагностическими метаданными снимков состояния.
- `shutdown` выполняет упорядоченное и непрерываемое завершение. Таймаут или отмена не отделяют очистку от завершения и не обещают немедленного возврата. `awaitState` и `awaitIdle` можно отменять; снимок состояния доступен во время Closing и в конечном состоянии.
- Составной Cause с Die+Fail/Interrupt или несколькими Die консервативно считается возможной ошибкой отката и запрещает перезапуск. Это безопасное поведение, но из-за него даже составная ошибка только на этапе создания иногда требует нового экземпляра механизма управления. См. ADR 0002.
- `retry` ничего не делает, если сервис не находится в состоянии Failed без изоляции. `awaitIdle` ждёт также завершения управляемых вызовов, но не фоновых задач сервиса, ограниченных Scope, и не наблюдателей за условиями запуска.
- Статический Context фиксируется при make. Произвольное распространение изменений Layer FiberRef и механизма выполнения дальше по графу не гарантируется.
- TypeScript не может запретить все случаи утечки экземпляра сервиса и неучтённые Promise. Пользовательский код, который не реагирует на отмену, способен удерживать Stopping или shutdown.
- Почтовый ящик не теряет сообщения и не реализует сложного ограничения потока. Снимки показывают состояние, а не журнал аудита. Необработанный Cause может содержать чувствительные данные; для журналов предусмотрен `safeSummary`.
- Не проверялись выполнение в браузере, другие предварительные или основные версии Effect и отдельный путь выполнения в Node. CI в GitHub Actions прошёл для текущей ветки `main`; выпуск по тегу через OIDC ещё не запускался.
- Библиотека не содержит сети, базы данных, пользовательского интерфейса, HMR, загрузчика расширений, нескольких поставщиков одного сервиса, распределённых владений и замены без периода недоступности.
